# M40 tenant governance and consented support

V34 adds typed, versioned support grants, independent governance review requests, monotonic tenant lifecycle state, legal holds, immutable operation responses and append-only audit events. No tenant data deletion is implemented or granted.

A current scoped merchant owner consents to one named support operator, one company/branch and an expiry of at most 24 hours. A different enrolled platform operator approves. Support access checks active platform enrollment, exact named operator, approval, expiry and revocation on every request. The only exposed diagnostic is three aggregate counts (products, posted sales, stock positions); it returns no names, ledger values, records or credentials. The operator remains the recorded actor. Revocation is available to the current scoped owner and serializes against diagnostic access. There is no impersonation, support write capability or unconsented break-glass path.

Suspension/resumption and legal-hold placement/release require a separate enrolled requester and approver. Approval validates the target epoch/version again. Commands persist exact original responses under tenant/operation keys; changed payload or actor reuse is rejected. Database guards enforce immutable identities, review provenance and monotonic transitions. Legal holds retain their placement/release history; no retention executor or export-completion certificate is fabricated.

`TenantLifecyclePolicy.requireNewMutation()` holds a shared transaction advisory lock; governance approval takes the matching exclusive lock. This includes tenants without a lifecycle row, so a first suspension cannot overtake an already admitted mutation. Suspension retains reads and recovery controls. Resume increments the tenant epoch and mutations require a newly issued JWT with the matching `tenant_epoch`; external IdP claim issuance remains an integration responsibility. `requireSuspended(decisionId, epoch)` checks the current independent suspension receipt under the same transaction fence for recovery planning. Legacy tenants with no lifecycle decision remain active at epoch zero without requiring a new token claim.

`PostgresPlatformGovernanceTest` exercises actual PostgreSQL RLS, exact replay, independent support approval, aggregate diagnostics and actor audit, revocation, suspension versus in-flight mutation locking, independent legal hold release, injected audit failure rollback, stale/missing/fresh token epochs, revoked platform enrollment and lack of deletion privileges. Source is ready for the root's serialized Maven run; execution evidence is recorded by the root after running the test.

Operational scope: list endpoints return the latest 100 records. Diagnostics intentionally support only the fixed aggregate surface. No arbitrary query execution, data export delivery, data erasure, retention-policy scheduling, support impersonation or external identity-provider administration is claimed.
