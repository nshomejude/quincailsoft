# Recovery receipt review

`/api/v1/operations/recovery` implements the bounded receipt review phase of Architecture §41. It preserves incident/source references, a preservation directive, immutable candidate receipts, scoped differences, independent approval and an actual current tenant suspension receipt/epoch. Every command has durable replay protection, audit and outbox records. Candidate uploads are sequential, versioned and bounded; receipt exports expose hashes and identities, never original response payloads.

States: REQUESTED → COLLECTING → MATCH_REVIEW_REQUIRED → RECEIPTS_REVIEWED. Differences instead enter DIFFERENCES_QUARANTINED; unfinished plans may be cancelled without deleting evidence. Scope approval and final receipt review require a different actor from the maker. Reads and commands require current owner/finance membership plus operations:recovery:read/write/approve capabilities. Data is scoped to the current tenant/company/branch with forced PostgreSQL RLS. Comparison and final approval require TenantLifecyclePolicy.requireSuspended, which holds the lifecycle transaction fence. Final review also repeats source receipt comparison.

This is not a production restore. The API always returns applied=false and productionCutoverAllowed=false. Target time and artifact/egress references are recorded evidence, not verified backup completeness or egress isolation. Candidate collection compares retained accepted operation receipts against the currently fenced source; it does not reconstruct target-point business rows. A matching branch receipt set does not establish whole-tenant dependency closure, financial correctness, document recovery or provider reconciliation. No ledger repair, source overwrite, bank action, resume or cutover is exposed. The preservation directive is not an independently enforced legal hold; platform governance owns legal holds and tenant lifecycle decisions. Missing or expired response evidence is quarantined, not assumed correct.

Acceptance source: `RecoveryPostgresTest`, enabled only with QUINCAI_PG_TEST_URL. Uses real PostgreSQL migrations, runtime non-bypass-RLS role, JPA, audit/outbox and concurrent replay. Checks independent approvals, current authorization epoch, scoped exports, mismatch quarantine, immutable retained evidence, rollback on invalid fence, resumed-fence replay rejection and absence of journal entries. The lifecycle interface is a controlled test implementation here; real lifecycle locking/receipt tests belong to platform-control. No database acceptance result is claimed until the root runner executes this test.
