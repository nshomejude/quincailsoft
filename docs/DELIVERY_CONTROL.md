## Immediate control rules

- Backend Java 25 / Spring Boot 4; database PostgreSQL 18. No Python production routes or shadow ledgers.
- Audit before finalized new allocations. CLOUD intends onboarding/subscriptions/platform configuration, HR/payroll extension, deployment/recovery/security assurance; Desktop retains active migration, dataset integration and local preview. Exact scope is in the proposed register.
- Every assignment has acknowledgment, implementation, integration and verification as separate states. A comment/request does not imply Desktop executed it.
- Onboarding completion means an actual usable tenant/company/branch/owner with safe retry and lifecycle controls, not APPROVED_FOR_PROVISIONING.
- Original QuincaiSoft designs and sky-blue/navy/white branding must survive framework migration. Real analytics must preserve business meaning; raw record counts are not substitutes.
- Desktop integrates and runs the combined suite. Each author runs focused tests. CLOUD independently reviews evidence; production execution requires a known authorized target. Technical sign-off is scoped, not a legal or third-party security certificate.
- Mobile/WPF remain paused and explicitly excluded from current execution, not counted as finished.
- The user's four-hour deadline never permits fake acceptance, skipped security, provider-success fabrication, deleting evidence or declaring incomplete modules production ready.
