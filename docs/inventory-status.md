# Inventory workflow implementation status

Implemented in the local integration backend, with transaction ownership and idempotency delegated to server.command:

- Goods receipt posting validates approved/partially received purchase source, supplier, warehouse and aggregate remaining quantities; increases physical stock and updates weighted-average product cost. Purchase closes only when fully received.
- Approved receipt/issue adjustments change stock, preserve movement evidence, and reject insufficient merchant-owned serviceable quantity.
- Counts capture product versions and physical snapshot, accept explicit actual counts through the capture command, require approval, reject stale snapshots and duplicate product lines, and post actual counted variance.
- Same-branch/same-company warehouse transfers dispatch into explicit transit, then receive partial quantities. Destination only increases on receipt; quantities cannot exceed dispatched remainder.
- Customer custody supports partial collection with proof; deducts physical custody without a second sale/ownership posting.
- Fulfillment requires matching completed sale and proof; refuses completion while customer custody remains unresolved.
- Approved sellable customer returns and supplier physical returns enforce source identity, aggregate eligible quantity and finality. Physical-return evidence records quantities, carrying cost, warehouse and product version. Completed customer-return quantities remain unavailable for resale until a dedicated financial credit posts; cash/provider refunds remain separate.
- Approved zero-loss repack/assembly/disassembly changes component/output quantities and transfers weighted cost.
- Approved zero-loss cutting consumes one parent piece and creates an integer number of a distinct output product. The job records input/output product lineage, lengths, source versions, warehouse, actor, measurement evidence and exact transferred cost.
- Lot quarantine blocks affected aggregate available stock; evidence-backed recovery releases it and disposal decrements physical stock.

`change_stock(c,user,product_id,delta,warehouse_id=None,source=None,allow_custody=False)` is the integration entry point for all stock mutations, including existing sale completion. Product `stock_positions` maps warehouse IDs to decimal quantities; aggregate stock must reconcile. Legacy opening stock is assigned only when the branch has exactly one warehouse. Adding warehouses requires explicit opening balances.

Seventeen focused tests pass in tests/test_inventory_workflows.py: receipt/order, overreceipt rollback, count variance/staleness, custody partial/excess, transfer partial receipt/excess, custody protection, return finality, quarantine disposal, repack cost, scope/version, and cut finality, length/cost conservation, stale products, scope, missing evidence, fractional count, waste/kerf, valuation rounding and availability rejection. These are local domain tests, not production certification.

Still blocked: cross-branch inventory authority, exclusive transfer reservation, damaged/quarantine return inspection, loss-bearing transformation recipes, lot-level cut lineage, robust lot/serial attribution, fiscal recognition policy, journal integration, immutable movement tables, complete warehouse-opening UX and distributed offline reconciliation. Partial lot quarantine currently blocks the affected aggregate quantity; it is not complete traceability. Generic product and custody edits must protect server-derived balances. Count approval must accept Counting -> In review -> Approved. The capture command takes quantities keyed by every snapshot product and marks the measurement captured; posting rejects missing capture. Inventory operators can start/capture; manager authority is required for posting. All physical postings require a valid open financial period.

## Bounded cut workflow

`cut` commands `confirm-cut` and `complete` require an Approved record and manager approval authority. Payload: `output_product`, `warehouse`, integer `parent_version` and `output_version` matching current product versions, and nonblank `evidence_reference`. Existing record fields `parent_length`, `output_length`, `output_count`, `kerf`, `waste`, `unit` describe the approved physical measurement. It consumes exactly one input piece; it is not a multi-parent batch. Source/output must be distinct Active stock-tracked `piece` products in the same branch/company as the job and warehouse. Positive lengths must conserve exactly (`output_length * output_count == parent_length`), count must be integer, and kerf/waste must both be zero. Output weighted cost must conserve input carrying value exactly at six-decimal precision or posting is rejected. Product balances and job status are updated atomically by the command transaction; final jobs cannot be posted again.

This is product/job lineage only. It does not certify physical dimensions against a master recipe, allocate traceable lots/serials, implement saw kerf or scrap, or post a stock transformation journal. Operators must select the output SKU corresponding to the approved dimension and attach measurement evidence. Loss-bearing and non-exact valuation jobs remain blocked rather than silently losing stock value.

Customer-return costing is deliberately bounded: physical receipt preserves the current product unit cost and records it as evidence. Financial credit must reject any mismatch against the immutable original-sale cost allocation. No silent revaluation or cash refund occurs. Historical completed returns without matching evidence require reconciliation.
