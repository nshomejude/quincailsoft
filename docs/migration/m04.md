# M04 — catalog and inventory migration

Java25 / Spring Boot4 / Hibernate JPA / PostgreSQL18 implementation governed by ARCHITECTURE §§2.2–2.3,3,32–38. No Python backend calls.

## Implemented

- Catalog create/update with integral XAF price strings, SKU/name/unit limits, tenant/company scope, immutable base unit, optimistic version checks, command idempotency, immutable response replay and outbox evidence. Stock quantities are not catalog form fields.
- Scoped warehouse picker and stock balances expose quantity, reserved/delegated quantity and carrying value. Picker includes authorized sales/purchasing workflows; inventory balance values require inventory read authority.
- Same-branch/same-company transfer draft, independent approval, dispatch into explicit outstanding transit, partial receipt and final receipt. Destination stock changes only on receipt; quantity and value cannot exceed the transit remainder. Source/destination identity and approved quantities remain immutable. Valuation must be exactly representable in integral FCFA. Period guards, retries and stale versions are enforced.
- Merchant-serviceable physical counts as per-product warehouse jobs: start stock/version/value snapshot, capture observed count with evidence, independently approve, post. Changes since the snapshot block posting. Shortage cannot silently consume reservations/allocations. Gain/loss changes stock and balanced operational journal atomically. Zero opening balance gains require an explicit acquisition-valuation workflow and are rejected by this count path.
- Approved zero-loss cutting: one source piece, distinct output SKU, whole output pieces, exact integer-millimetre length conservation and full carrying-value transfer. No kerf/waste accounting is fabricated.
- Approved zero-loss repack/assembly/disassembly recipe: distinct source/output SKU, positive exact milli quantities, evidence reference, full carrying-value transfer. Use reversed source/output recipe for disassembly. An independent approver accepts the quantity recipe; issued cost is frozen at posting.
- All job state transitions have command operation IDs, version checks, reasons, actor evidence and outbox events. Final jobs are immutable. Count stock locks follow warehouse-before-balance ordering, consistent with ordinary stock changes.

## Verification

`PostgresInventoryWorkflowTest` executes V1–3/V6/V7 on real PostgreSQL18 with non-owner runtime identity and JPA schema validation. It checks catalog create/update/replay/version/unit constraints; transfer maker-checker, dispatch availability, partial/excess receipt, value conservation, closed-period rollback and replay; count independent approval, journal loss, repeat post and stale snapshot; zero-loss cut/repack stock and cost conservation and invalid cut rejection. The inventory module also retains seven stock invariant unit tests. Root integrated verification is authoritative.

## Still not migrated/certified

Full third-party custody/ownership dimensions, lot/serial/quarantine attribution, cross-branch authority, transfer loss investigation, exclusive reservation/grant issuance, count sheets covering multiple products as one approval batch, arbitrary direct adjustments, damaged returns, lossy cutting/repack recipes, fractional-FCFA WAC rounding policy, multi-price-list/promotions/alternate-unit catalog, barcode/media management and complete field-device concurrency matrix remain required. The new job handlers are concrete bounded workflows, not certification of the full inventory module or native/offline operating model.
