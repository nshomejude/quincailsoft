## Implemented behavior

- Native Expo Router shell with workspace, catalog, sales and durable queue tabs; product and sale detail routes resolve explicit IDs through Java APIs and work independently of prior list selection.
- OIDC Authorization Code + PKCE in the system browser, HTTPS issuer/API requirements, scoped Java session bootstrap, OS SecureStore token storage, expired-session sign-in, local sign-out preserving queued facts. No public-client secret, password authentication shim or browser localStorage token.
- Catalog search/refresh/details; sales listing/details with line amounts, customer, warehouse, date and version; exact-string quantity input; scoped Java product/customer/warehouse selection; durable local sale-draft capture and explicit queue transmission. Only draft creation is implemented from mobile; the UI does not claim stock/money posting.
- Scope-specific SQLCipher SQLite database, random 256-bit key in OS SecureStore, WAL + synchronous FULL, transactional enqueue, immutable source-field/deletion triggers, retry using original operation IDs, persisted acceptance receipts, interrupted-send recovery and one sync coordinator per opened database. Missing native SQLCipher fails closed without a plaintext fallback.
- DRAFT, COMPLETED_AUTHORIZED and COMPLETED_EXCEPTION are distinct local classifications. Completed evidence is retained as REVIEW_REQUIRED and never transmitted to ordinary draft creation. HTTP rejection and offline ambiguity preserve the original source; disk-full/failed transaction cannot report durable success. No automatic eviction or receipt deletion is implemented.
- Java RSA device challenge/proof, short challenge expiry, actor binding, current database owner approval, version checks, random UUID epochs and immutable tenant-scoped idempotency receipts. Proof requires RSA >=2048-bit key possession; it does not establish hardware attestation.
- Owner-only signed recovery quarantine, exact UTF-8 payload hashing, epoch/scope/sequence binding, preservation of conflicting signed histories, own-actor operation-status lookup, tenant/company/branch forced RLS, immutable recovery records and transactional audit events for challenge/proof/approval/intake.
- The shared language-neutral contract in packages/sync-protocol documents exact routes, JSON schema, DTO fields and RSA canonical signing bytes. The .NET adapter peer aligned to these contracts. Recovery returns businessPosted=false and device approval returns offlineSelling=false.

## Remaining implementation and external gates

1. Native build infrastructure and test devices: Android SDK/Gradle and iOS/Xcode signing/builds, Keychain/Keystore behavior, SQLCipher at-rest verification, backup exclusion, device loss/reinstall recovery, battery/background behavior and accessibility testing.
2. Actual OIDC deployment: register the public mobile client, scoped permissions, HTTPS API and `quincaisoft` redirect, verify Android/iOS deep links, MFA/step-up policy, remote revocation/session renewal and deployed login. Environment values are deployment inputs, not invented credentials.
3. Full native role modules N01–N40 remain beyond implemented catalog/sales-draft/detail/queue surfaces: owner reports, approvals, cash shifts, stock count/receiving/transfers, delivery evidence, barcode/camera, notifications, documents/printers, EN/FR and every workflow's empty/error/conflict/accessibility states. No overall native screen-completeness claim.
4. Exclusive stock/credit grant issuance must be implemented atomically by inventory ownership APIs before offline economic posting can be enabled. Required work includes signed grant snapshots, quota consumption, device fencing, hardware key enrollment, trusted revocation timeline, local journal/document atomicity, grant expiry/reconciliation and adversarial allocation tests. Current sync deliberately issues no grants.
5. Recovery intake preserves evidence but does not implement finance suspense/clearing, economic resolution, affected-allocation freeze, epoch replacement/revocation workflow or accepted sequence/hash checkpoints. No completed payload is treated as an approved sale merely because its device signed it. Mobile currently cannot create signed completed facts; imported completed records remain local review evidence.
6. Commit-safe signed change feed, transactional snapshot/resnapshot, receipt-retention horizon policy and encrypted owner-approved support bundle export remain unimplemented. Queue sources/receipts are presently retained indefinitely rather than evicted.
7. Standalone Windows companion signed/encrypted snapshots, offline pairing and draft import are a separate unimplemented deployment mode. This native client currently needs Java API/OIDC for online data and has encrypted local draft storage, not a claim of all standalone companion features.

Native build/deployment owner must close items 1–2; mobile lead items 3 and native portions of 4–7; inventory/sync/finance leads jointly own the economic authority and recovery gates. These are engineering and deployment gates, not user permission requests.
