# M05 — Next.js web migration evidence

## Architecture and scope

Implemented in `apps/web-admin` against the Java API only, retaining Next.js 16, React, strict TypeScript, pnpm, OIDC Code+PKCE, Redis server sessions and authoritative Java scope/RBAC. Added TanStack Query, React Hook Form/Zod, Lucide and shared EN/FR shell dictionaries. No Python proxy, fake ledger, browser OAuth token storage or generated pretend screen completion was introduced.

Reviewed `ARCHITECTURE.md` canonical web/security/precision requirements and `v3/contracts.json`: **152 screen references, 76 report references, 26 document references and 70 entity schemas**. Those legacy counts are requirements references, not implemented or certified migration counts. Routes below represent actual implemented Java-backed workflows and deliberately do not imply parity with every legacy tab/field/report.

## Interaction and safety behavior

Forms expose loading, backend errors, successful response and current versions. The finite BFF method/path allowlist rejects arbitrary upstream paths and destructive methods, checks same Origin, validates command identity and adds request/idempotency headers. Tokens are retained exclusively on the server. Read tables and forms use current Java authorities; hidden navigation never replaces server checks. Relationship IDs come from available scoped APIs, with identity account UUIDs shown because no identity display-name API exists. No stock/payment mutation is optimistically treated as posted. Exact XAF and milli-unit values remain strings/BigInt; reports never convert monetary strings to Number.

Reports show totals only when supplied; their totals cover the whole filter, not just the current page. Provider reports deliberately do not total mixed environment/currency intents. CSV exports are labelled as selected-page exports. Document HTML is isolated in a sandboxed print route with a restrictive CSP and no-store response.

## Explicit remaining gaps

- Not every legacy screen, field, analytical report or document template is migrated. Backend-unavailable workflows are not rendered as fake working forms. In particular full POS fulfilment/dispatch/reservations, product category/brand/barcode/pack/pricing tiers, complete customer CRM/credit configuration, bank reconciliation, tax administration, subscriptions/platform tenancy, import pipelines, webhooks/support/operations and storefront remain outside the delivered Java contracts.
- Five implemented report families do not replace all 76 named report definitions; immutable Java snapshots/settings do not constitute all 26 templates or a template designer.
- EN/FR shell/navigation/loading is implemented; domain forms, validation text and reports remain predominantly English. Full bilingual acceptance remains open.
- Existing palette/responsive CSS is retained. Complete Tailwind/shadcn component migration, generated OpenAPI client and comprehensive accessibility/device/browser evidence remain open.
- Supplier return command is wired but supplier-return history/detail and net invoice-after-return workflow remain backend/UI acceptance gaps. Customer returns support the bounded sellable-stock workflow implemented by Java.
- Expense payer needs `cash:read` to select a current cash session. Related-resource read permissions must be present in deployed role profiles; frontend intentionally does not bypass Java permission failures.
- Role change approval is implemented, but role/IdP provisioning, MFA, recovery, rotating refresh tokens and full authorization epoch/session lifecycle require deployment acceptance. No multiple local password login stores were introduced.
- MTN live/sandbox collection delivery, asynchronous callbacks and reconciliation need provider credentials and actual environment verification. Orange remains unavailable until a genuine contracted adapter is configured; no UI marks it integrated.
- Lists with bounded Java result sets are displayed as returned records; this is not complete historical pagination. Dedicated expense detail currently resolves within the returned scoped expense list because no GET expense-id contract exists.
