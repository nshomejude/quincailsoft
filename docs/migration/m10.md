# Migration 10: reporting, contracts and acceptance register

This slice implements five bounded reports in Java 25 / Spring Boot 4, with jOOQ reporting reads. It does not claim that all 76 canonical report definitions, 152 screens, 26 document templates, or their fields and workflows have been accepted.

## Implemented queries

| Code | Actual basis | Summed values |
| --- | --- | --- |
| posted-sales | Posted/returned sale records by original business date; subsequent returns are not netted | Original revenue, recognized original cost, margin |
| stock | Current merchant-owned serviceable positions with SKU, unit and reserved/allocated quantities | Value XAF only; mixed units are not added |
| receivables | Current per-sale outstanding receivable projection | Outstanding XAF; not deposits, aging or all customer credits |
| cash | Cash sessions by business date; opening plus immutable cash movements | Opening, movement and expected XAF |
| provider-intents | Provider intent requests/status by business date; sandbox and live labeled | None: request amounts are not collections and currencies/environments differ |

GET `/api/v1/reports/catalog`, GET `/api/v1/reports/{code}` and GET `/api/v1/reports/{code}/export` require server-side report permissions. Read/export authority expressions are recorded in OpenAPI. Dated reports require an inclusive range of at most 367 dates. Current stock/receivables reject historical date arguments. Offset is 0–100000 and page size 1–1000.

Rows and amounts are strings, preserving values beyond JavaScript safe integers. Window totals and page rows share one PostgreSQL statement snapshot; totals cover the full filtered result, and empty pages have no totals. CSV exports only the requested page, escapes quotes and prefixes spreadsheet formula-like cells. `X-Report-Has-More` identifies additional pages; this is not an asynchronous complete export job. Pagination across separate requests can observe concurrent source changes.

`V10__versioned_reporting_projections.sql` defines five versioned read contracts as PostgreSQL security-invoker views. Underlying RLS remains active, and jOOQ adds explicit tenant/company/branch predicates inside the shared scoped transaction. The module never writes another module's tables. Provider phone numbers/references are excluded from these reports.

## Source contracts and SDK

`packages/api-contracts/generate-source-contract.mjs` extracts real controller methods, paths, record shapes and authorization expressions. It expands action-regex routes and accounts for inherited mandatory X-Request-ID on `/api` commands. This is a source-shape extractor, not a claim that all business validation, nullability, error variants and consumer behavior have been contract-tested. Dynamic Object payloads remain unknown. Separate platform `/admin` paths must target the isolated deployment and token audience.

`packages/generated-ts-sdk/schema.d.ts` is actual pinned openapi-typescript 7.10.1 output. The handwritten adapter uses openapi-fetch 0.15.0. Clients have not all been switched to this SDK. Regeneration and structural checks are reproducible; the canonical register must be refreshed after sources change.
