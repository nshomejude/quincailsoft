# Assignment 02 — operational export producer and protected downloads

Preflight: AGENTS.md; architecture §§43.3/44.3 and D22/Q046/Q053; historical migration summary, canonical migration coverage, complete Python parity inventory; legacy server/policy.py `allow` export check and role table. Existing Java OperationsService records, OperationalReads fixed projections, Csv writer and V17/V40 export constraints were read. There is no legacy end-to-end export worker to invent parity against. This is implementation of the specified Java replacement.

Owned files: ExportService, DefaultExportService, ExportController, ExportJobPostgresTest and OperationalReads.csv only. No accepted SQL, recovery, retention or shared receipt code is changed. The broad OperationsService remains unimplemented; a focused export API avoids fake stubs for import/notifications/recovery.

Behavior: explicit scoped actor-owned request → QUEUED → READY/FAILED/CANCELLED; one queued export per tenant; serialized actor-owned run; one-hour expiry; same-transaction receipt, audit and outbox; optimistic version checks; 100-entry history cap. Native reads use fixed, explicit tenant/company predicates plus forced RLS. Catalog/customer/supplier master data are company-wide models; export jobs remain actor/branch-owned. CSV formula escaping is reused. Payload bound counts UTF-8 bytes, not Java characters. A bound-exceeding job becomes FAILED without retaining a partial payload. Download is authenticated, no-store, and checks current membership/epoch, explicit export/entity-read permissions, original owner, expiry, READY state and SHA-256 integrity. Revoking permission blocks run/download; changing authorization epoch invalidates prior exports. Current authorized original actor can cancel an old queued job after an epoch change to release admission.

Security limits: CUSTOMER export fails closed because action/resource-bound step-up verification required by §44.3 is not yet implemented. A generic scope or MFA claim is not substituted. Existing role policy is intentionally narrowed to current owner/finance plus exact capability checks. Revocation cannot retract already downloaded bytes. SUPPLIER exports use the existing fixed projection including bank reference and require supplier read and operations export capabilities; full sensitive-data step-up policy still needs shared identity capability before release.

Acceptance source: ExportJobPostgresTest uses PostgreSQL 18 runtime role without superuser or RLS bypass, applies migrations, validates JPA, and executes real job transitions. It covers concurrent identical completion, conflicting identity, queue admission rollback, missing capability at run/download, member-role and epoch denial, cross-company payload isolation, other actor/branch denial, CSV formula safety, terminal immutability, cancellation, row bounds, true UTF-8 byte bounds, expiry and no partial failed payload. Root executes Maven and records actual results; this document does not claim unexecuted tests passed.

Remaining: automated asynchronous worker scheduling and fair queue load benchmark, partitioned/streaming 200,000-line export, customer action-bound step-up, full privacy policy acceptance, export UI/visual acceptance and live HTTP/OIDC checks. The bounded run endpoint is a real executable workflow, not a claim that D22's large asynchronous export is complete. Original broad import/notifications OperationsService gaps are outside this assignment. No blanket migration completion claimed.
