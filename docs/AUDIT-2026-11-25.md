## Gaps (ranked by launch impact)

### P0 — blocks going live at quincaisoft.com
1. No deployment artefacts: no Dockerfiles, no reverse-proxy/TLS config, no CI, no process manager. Only a dev-only Postgres compose file.
2. No public marketing site. quincaisoft.com has nothing to serve; the root `index.html` is a labelled "LOCAL DEMO · synthetic data" legacy prototype.
3. Login needs an OIDC provider (not in repo) + Redis + Java 25 API + PostgreSQL 18. None exist in infrastructure/. Without an IdP nobody can sign in.
4. Failed login is silent: `/auth/callback` redirects to `/?auth=failed` and `app/page.tsx` never reads it.

### P2 — design inconsistencies
- Three UI generations coexist: legacy static (`index.html`, `pages/` 152 files, `v3/`, `v4/`), Next.js admin, and a bare storefront. Different CSS, different branding (storefront has no logo/nav).
- i18n: 21 keys in en/fr, nav only. Every page body, form label and error is hard-coded English despite the "bilingual from inception" rule. Storefront is `lang="en"` fixed.
- Navigation: Returns uses the Sales icon; Expenses/Periods/Cash share one icon; no grouping, no mobile/responsive collapse of sidebar.
- Currency formatting: storefront uses `fr-CM`, admin has own `xaf()`.
- Minified one-line source files (layout/page/proxy) — unmaintainable and hard to review.
- Error UI is generic ("Unable to load this view"); no 404/403 pages in admin; no empty states.

### P2 — bugs / risks found
- `/auth/callback` swallows all errors with no log or correlation id.
- Session lifetime = token TTL (max 1h) with no refresh token; users are logged out hourly and lose form state.
- Storefront uses `cache:'no-store'` on every request: every product view hits the API; no ISR/caching, slow and un-CDN-able.
- Storefront product page refetches the entire catalogue to display one product.
- Storefront + platform-admin lack the security headers web-admin has (X-Frame-Options, Referrer-Policy, CSP, HSTS).
- No rate limiting on `/auth/login`.
- Redis session key has no binding to user agent/IP (acceptable, note only).
- Mobile: authorised offline posting disabled; native builds unverified.
- Windows desktop adapter: R02 baseline has vulnerable dependencies (per repo's own evidence).
- Orange Money unavailable (contract pending). MTN tested only against simulated transport.

## Proposed fix order
1. Deployment package (Dockerfiles, compose, Caddy/nginx TLS, CI) + login error handling + security headers.
2. Public site: bilingual marketing pages + full SEO/GEO/AEO layer, storefront SEO + caching.
3. Customers, commerce publishing, branches, sales void/print, dashboard.
4. Reports and document templates, in batches.
5. i18n pass on all pages.
